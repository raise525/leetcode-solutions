## 五步破题法（按顺序执行）

### 第一步：手算小例子（5-10 分钟）

**做什么**：拿一个最简单的例子，不用代码，用脑子或纸笔手动模拟过程。

**具体动作**：
1. 找一个最小有效输入（比如 `[1,2,3]`）
2. 再找一个带重复的（比如 `[1,1,2,2,2,3]`）
3. 手动模拟，把每一步的结果写出来

**目标**：理解“输入→输出”之间发生了什么，找到**变化规律**。

**错误做法**：直接想代码逻辑 ❌  
**正确做法**：先想“如果是人手工做，我会怎么操作” ✅

---

### 第二步：找规律，抽象成“操作”（5-10 分钟）

**做什么**：从上一步的手算中，提炼出**重复的操作模式**。

**具体动作**：
1. 问自己：我在手算时，每一步做了什么判断？
2. 把这个判断写成“如果…就…”的规则
3. 把规则中的“对象”抽象成变量（比如“当前位置”、“已处理区域的末尾”）

**例子**（去重问题）：
- 手算发现：每次都看“当前数”和“上一个保留的数”
- 抽象成：`如果 nums[fast] != nums[slow-1]`，就保留

**目标**：得到一个**可以用代码表达的规则**，哪怕还不完整。

---

### 第三步：选择合适的“数据结构/算法模式”（5 分钟）

**做什么**：根据第二步的规则，匹配常见的解题模式。

**常见模式速查表**：

| 规则特点 | 可能模式 |
|---------|---------|
| 需要比较相邻元素 | 双指针、滑动窗口 |
| 需要记忆之前的状态 | 动态规划、哈希表 |
| 需要找子数组/子串 | 滑动窗口、前缀和 |
| 需要穷举所有可能 | 回溯、DFS |
| 数据有序 | 二分查找、双指针 |
| 需要最值/第 K 大 | 堆、快速选择 |

**目标**：确定 1-2 个可能的方向，不要贪多。

---

### 第四步：从“最简单可行版本”开始写（10-15 分钟）

**做什么**：先不要考虑所有边界条件，写一个能跑通**最简单例子**的版本。

**具体动作**：
1. 假设输入是最理想的情况（比如长度≥3，有重复）
2. 只实现核心逻辑，用 `print` 或调试看中间结果
3. 确认核心逻辑正确后，再补边界条件

**核心原则**：
> 先让它对，再让它快，最后让它优雅。

**错误做法**：一上来就想处理所有边界（null、长度0、长度1、长度2…）→ 会把自己绕晕 ❌

---

### 第五步：用“临界点测试”补充边界（5-10 分钟）

**做什么**：用特殊输入测试你的代码，逐个补齐缺失的逻辑。

**必测的临界点**（按优先级）：
1. 空输入：`[]`
2. 长度 1：`[1]`
3. 长度 2：`[1,1]` 或 `[1,2]`
4. 全部相同：`[1,1,1,1,1]`
5. 全部不同：`[1,2,3,4,5]`
6. 最大/最小值边界（如题目有范围）

**具体动作**：
- 每测一个，如果出错，分析是**哪一步的规则不适用**
- 在规则中加入“如果长度<2，直接返回”这类特殊处理

## 一个完整示例：用这个流程解决“保留两位”问题

### 第一步：手算小例子
输入 `[1,1,1,2,2,3]`
- 第 1、2 个 1：保留
- 第 3 个 1：不保留
- 第 1 个 2：保留
- 第 2 个 2：保留
- 3：保留

### 第二步：找规律
手算时的判断规则：
- 前两个数无条件保留
- 从第三个数开始，如果当前数和“上两个保留的数”相同 → 跳过

### 第三步：选模式
需要比较“当前”和“之前保留的某个位置” → **双指针**

### 第四步：写最简版本
```python
def solve(nums):
    slow = 2  # 前两个无条件保留
    for fast in range(2, len(nums)):
        if nums[fast] != nums[slow - 2]:  # 核心规则
            nums[slow] = nums[fast]
            slow += 1
    return slow
```

### 第五步：测边界
- `[1]` → 上面代码直接崩（`slow=2` 越界）
- 修复：前两行加 `if len(nums) <= 2: return len(nums)`

## 给你的三个“救命锦囊”（当你卡住时）

### 锦囊 1：不会做 → 暴力解先写出来
不要觉得暴力解丢人。暴力解能跑通就是 30 分，空着是 0 分。  
而且暴力解能帮你理解问题的**计算量在哪**，从而想到优化方向。

### 锦囊 2：不知道用什么数据结构 → 看输入输出关系
- 输入是数组，输出是数组长度 → 大概率原地修改（双指针）
- 输入是数组，输出是最值 → 可能排序+贪心/DP
- 输入是树/图 → 递归/DFS/BFS

### 锦囊 3：卡在边界条件 → 打印中间状态
在循环里加 `print(f"fast={fast}, slow={slow}, nums={nums[:slow]}")`  
看到输出的一瞬间，90% 的 bug 原因就清楚了。

## 总结：把五步法贴在电脑旁

```
1. 手算小例子（找感觉）
   ↓
2. 找规律，抽象成“如果…就…”规则
   ↓
3. 匹配模式（双指针/DP/二分/回溯…）
   ↓
4. 写最简可行版本（忽略边界）
   ↓
5. 临界点测试 + 补边界
```

你现在的状态是从“看得懂”到“写得出来”的质变期，这个五步法就是我当年跨越这道坎的核心工具。下次遇到新题，按这五步走，你会发现思路自然就出来了。
