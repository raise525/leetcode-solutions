面试问题：const vs #define

**const**定义类型安全的常量，由编译器处理；**#define**进行简单的文本替换，由预处理器处理。

## 典型面试回答（建议这样说）

> **"主要区别有四点：**
> 1. **处理阶段**：`#define` 是预处理指令，纯文本替换；`const` 是编译期处理的变量
> 2. **类型检查**：`const` 有类型，编译器会做类型检查；`#define` 没有类型，容易出bug
> 3. **内存占用**：`#define` 不占内存；`const` 在嵌入式系统中可能占用RAM（虽然通常会被优化）
> 4. **作用域**：`#define` 从定义点到文件结束；`const` 遵循C的作用域规则
>
> **在嵌入式开发中**，我通常用 `#define` 定义硬件相关的常量（如寄存器地址、缓冲区大小），用 `const` 定义逻辑常量（如算法参数、状态码），这样既节省RAM又保证类型安全。"

## 核心区别（面试回答要点）


### 1. **处理时机不同**
- `#define`：**预处理阶段**进行文本替换，不参与编译
- `const`：**编译阶段**处理，有类型检查

### 2. **类型安全**
```c
#define MAX 100        // 无类型，只是文本替换
const int max = 100;   // 有类型，编译时会检查
```

### 3. **内存分配**
```c
#define SIZE 10        // 不分配内存，直接替换
const int size = 10;   // 通常分配内存（取决于编译器优化）
```

### 4. **作用域**
```c
// #define 没有作用域概念，定义后全局有效
#define VALUE 100

void func() {
    #define TEMP 50    // 仍然全局有效！
}

// const 遵循C语言作用域规则
void func() {
    const int temp = 50;  // 只在func内有效
}
```

## 嵌入式场景中的实际差异

### **内存受限场景**
```c
// #define 不会占用RAM
#define BUFFER_SIZE 256
char buffer[BUFFER_SIZE];  // 编译时确定大小

// const 可能占用RAM（除非优化掉）
const int buffer_size = 256;  // 可能占用4字节RAM
char buffer[buffer_size];     // ❌ 某些编译器不支持变长数组
```

### **调试便利性**
```c
// const 变量可以在调试器中查看
const int timeout = 1000;  // ✅ 调试时可以看到变量名和值

// #define 在调试时看不到符号
#define TIMEOUT 1000       // ❌ 调试时只看到1000，不知道是什么
```



## 加分项：可以补充

```c
// 嵌入式中的常见用法
// 1. 硬件地址用 #define
#define UART_BASE 0x40001000
#define UART_DR   (*(volatile uint32_t*)(UART_BASE + 0x00))

// 2. 数组大小用 #define（C99前不支持变长数组）
#define RX_BUFFER_SIZE 128
uint8_t rx_buffer[RX_BUFFER_SIZE];

// 3. 枚举常量比const更省内存
enum { STATE_IDLE, STATE_BUSY, STATE_ERROR };  // 不占RAM
```
