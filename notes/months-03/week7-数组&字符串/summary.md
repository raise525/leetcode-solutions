如果要**把这几道题当成一个整体**，找出它们背后**共通的、反复出现的解题方法**，可以总结为以下**3条核心共性**：

### 1. 双指针技术
这是这几道题里出现频率最高的**通用手段**。

-   **体现：**
    -   #58 （一个指针跑，一个指针记录单词起点）
    -   #28 （暴力匹配时，两个指针分别遍历主串和模式串）
    -   #76 （外观数列：一个指针定位当前字符，一个指针向前数有几个相同的）
    -   #14 （纵向比较时，其实也可以看作是列指针在移动）
-   **总结：**
    字符串本质是字符数组，**只要涉及到“遍历”和“比较”**，双指针（或快慢指针）往往是物理意义上的最直接操作方式。

### 2. 哈希表辅助记录
当题目出现“是否存在”、“重复”、“历史记录”这类关键词时，哈希表是通用的优化工具。

-   **体现：**
    -   #217 （HashSet记录已出现元素）
    -   #219 （HashMap记录元素最近一次出现的下标，用来和当前窗口比较）
-   **总结：**
    很多字符串问题在暴力解法下需要两层循环，而引入**哈希表**可以把“查找历史”的时间复杂度从 O(n) 降到 O(1)。这是一种典型的**空间换时间**的共性思维。

### 3. 滑动窗口思想
这是处理**“连续子串/子序列”**问题的通用模型。

-   **体现：**
    -   #219 （显式的滑动窗口：维护大小为 k 的窗口）
    -   #76 （外观数列：本质上也是在滑动一个窗口，统计窗口内连续相同字符的个数；窗口的边界就是字符变化的边界）
-   **总结：**
    当题目涉及**“连续”、“相邻”、“最近 K 个”**这些概念时，**滑动窗口**是一个通用的解题框架。右边界负责探索新元素，左边界负责剔除过期元素。

### 终极提炼：一个“通用解题三板斧”

如果把这几天刷的题看作一类问题（**字符串遍历 + 条件判断**），它们的共性解法可以归结为：

1.  **怎么走？** 用**指针**（单指针、双指针、快慢指针）从头到尾或从尾到头扫描。
2.  **记什么？** 用**哈希表**记录已经见过的字符或位置，方便快速查重。
3.  **框多大？** 如果涉及“连续范围”，就用**滑动窗口**来动态调整当前关注的范围。

所以，这几道题其实是在反复训练你：**“拿到字符串，先想清楚指针怎么移动，需不需要用哈希表记点东西，以及需不需要维护一个窗口。”**



指针小课堂：
1. int a = 10;   你在小区里买了一个房间，里面住着整数 10，这个房间的门牌号是 0x100。
2. int *p = &a;  p是个指向int类型的指针，他存储的是一个地址，你手里拿了一张纸条，上面写着“门牌号 0x100”。
3. int **q = &p;  q是一个指向int*类型的指针，一张新的纸条 q。你在这张新纸条 q 上写了一行字：“纸条 p 放在 0x200 房间”。

- q 本身是一张纸条。
- *q 的意思是：按 q 找过去，你看到了一个房间，里面放着一张纸条。你打开那张纸条（*q），发现上面写着一个门牌号。
- **q 的意思是：按 q 找过去，拿到里面的那张纸条，再按那张纸条上的门牌号找过去，最后看到那个房间里的整数。
