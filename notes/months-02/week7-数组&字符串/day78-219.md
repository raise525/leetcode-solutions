## #219 存在重复元素 II

**【题目描述】**
给你一个整数数组 nums 和一个整数 k，判断数组中是否存在两个不同的索引 i 和 j，满足 nums[i] == nums[j] 且 abs(i - j) <= k。如果存在，返回 true；否则，返回 false。

**【关键词】**
哈希表 | 滑动窗口 | 索引记录

**个人的思路**
1.  找重复 → 找一个基准往后对比 → 双重循环暴力求解，但是有限制K，只需要限制向后遍历的长度就好了
2. 因为暴力求解时间复杂度为 O(n²) → 通过遍历数组并将元素放入哈希表，但也要限制哈希表的大小，超过之后就把前面的删掉
3. 因为题目中有个限制，在k个长度里 → 滑动窗口

---

### **🧠 思维推导**

**由什么想到什么：**
```
重复元素 + 索引差约束 → 需要记录每个元素最近出现的位置 → 哈希表（值→索引）
            ↓
  固定窗口大小 k → 只需维护最近的 k 个元素 → 滑动窗口 + 哈希集合
            ↓
  暴力解法 → 双重循环检查所有数对 → 但会超时（O(n²)）
```

---

### **核心技巧**

#### 一、哈希表记录索引法（最直观）

**核心思想：**
遍历数组，用哈希表记录每个元素最近一次出现的索引。当遇到重复元素时，检查当前索引与上次出现索引的差值是否 ≤ k。

**解题步骤：**
1. 创建哈希表 map，键为元素值，值为该元素最近出现的索引
2. 遍历数组，对于每个元素 nums[i]：
   - 如果该元素已在哈希表中，且 i - map[nums[i]] ≤ k，返回 true
   - 否则，更新哈希表，将当前索引 i 存入 map[nums[i]]
3. 遍历结束返回 false

**代码实现：**
```cpp
bool containsNearbyDuplicate(vector<int>& nums, int k) {
    unordered_map<int, int> lastIndex;  // 值 -> 最近出现的索引
    
    for (int i = 0; i < nums.size(); i++) {
        // 如果当前元素之前出现过，且索引差 ≤ k
        if (lastIndex.count(nums[i]) && i - lastIndex[nums[i]] <= k) {
            return true;
        }
        // 更新最近出现位置
        lastIndex[nums[i]] = i;
    }
    return false;
}
```

**复杂度：**
- 时间复杂度：O(n)
- 空间复杂度：O(n)

#### 二、滑动窗口法（维护 k 大小的窗口）

**核心思想：**
维护一个大小为 k 的滑动窗口，窗口内的元素不能有重复。用哈希集合判断当前元素是否在窗口内出现过。

**解题步骤：**
1. 创建哈希集合 window，用于存储当前窗口内的元素
2. 遍历数组，对于每个元素 nums[i]：
   - 如果 nums[i] 已在 window 中，说明窗口内有重复元素，返回 true
   - 将 nums[i] 加入 window
   - 如果窗口大小超过 k，移除最左边的元素 nums[i-k]（保证窗口大小 ≤ k）
3. 遍历结束返回 false

**代码实现：**
```cpp
bool containsNearbyDuplicate(vector<int>& nums, int k) {
    unordered_set<int> window;  // 存储当前窗口内的元素
    
    for (int i = 0; i < nums.size(); i++) {
        // 检查当前元素是否在窗口内
        if (window.count(nums[i])) {
            return true;
        }
        
        // 加入当前元素
        window.insert(nums[i]);
        
        // 保持窗口大小为 k
        if (window.size() > k) {
            window.erase(nums[i - k]);
        }
    }
    return false;
}
```

**复杂度：**
- 时间复杂度：O(n)
- 空间复杂度：O(k)

#### 三、暴力法（不推荐，会超时）

**核心思想：**
对每个元素，检查其后面 k 个范围内是否有相同元素。

**代码实现：**
```cpp
bool containsNearbyDuplicate(vector<int>& nums, int k) {
    for (int i = 0; i < nums.size(); i++) {
        // 只需检查后面 k 个元素
        for (int j = i + 1; j < nums.size() && j <= i + k; j++) {
            if (nums[i] == nums[j]) {
                return true;
            }
        }
    }
    return false;
}
```

**复杂度：**
- 时间复杂度：O(n × min(n, k))，最坏 O(n×k)
- 空间复杂度：O(1)

### **📊 复杂度分析（详细版）**

**一、哈希表记录索引法**

**时间复杂度：O(n)**

详细分析：
1. **操作分解：**
   - 遍历数组：n 次循环
   - 每次循环执行：
     * 一次哈希表查找（`.count()`）
     * 可能的一次索引差计算
     * 一次哈希表插入/更新（`[]` 操作符）

2. **哈希表操作分析：**
   - 平均情况：O(1)
   - 最坏情况（哈希冲突严重）：O(n)
   - 但实际应用中接近 O(1)

3. **总操作次数：**
   - 最好情况：找到满足条件的重复时提前退出
   - 最坏情况：无满足条件的重复，完整遍历 n 次
   - 比较次数 ≈ n 次查找 + n 次插入

**空间复杂度：O(n)**

详细分析：
1. **内存占用：**
   - 最坏情况：所有元素都不重复（或重复但索引差不满足），需要存储所有 n 个元素
   - 每个键值对存储：元素值（int）和索引值（int）
   - 加上哈希表节点开销，约 24-32 字节/元素

2. **最好情况：** 前两个元素就满足条件，只存储 1-2 个元素

3. **平均情况：** 存储的元素数量取决于数据分布

---

**二、滑动窗口法**

**时间复杂度：O(n)**

详细分析：
1. **操作分解：**
   - 遍历数组：n 次循环
   - 每次循环执行：
     * 一次哈希集合查找（`.count()`）
     * 一次哈希集合插入（`.insert()`）
     * 当窗口满时，一次哈希集合删除（`.erase()`）

2. **窗口维护：**
   - 插入和删除都是 O(1) 平均
   - 删除操作最多 n 次（每个元素最终都会被删除）

3. **总操作次数：**
   - 约 n 次查找 + n 次插入 + n 次删除 = 3n 次操作

**空间复杂度：O(k)**

详细分析：
1. **窗口大小控制：**
   - 哈希集合最多存储 k+1 个元素
   - 当 i > k 时，每插入一个新元素就会删除一个旧元素

2. **内存占用：**
   - 与 k 成正比，与 n 无关
   - 当 k 很大（接近 n）时，空间复杂度接近 O(n)
   - 当 k 很小（常数）时，空间复杂度 O(1)

3. **优势：** 空间效率比哈希表法好（当 k < n 时）

---

**三、暴力法**

**时间复杂度：O(n × min(n, k))**

详细分析：
1. **操作次数：**
   - 外层循环：i = 0 到 n-1
   - 内层循环：j = i+1 到 min(n-1, i+k)
   - 总比较次数 ≈ n × k/2（平均）

2. **具体数值：**
   - n=10⁴, k=10⁴：约 5000 万次比较
   - n=10⁵, k=10⁴：约 5 × 10⁸ 次比较
   - 会严重超时

3. **为什么不可行：** O(n×k) 对于大数据集是灾难性的

**空间复杂度：O(1)**
只使用循环变量，无额外空间

---

### **📈 各方法对比**

| 方法 | 时间复杂度 | 空间复杂度 | 优点 | 缺点 |
|------|-----------|-----------|------|------|
| 哈希表索引 | O(n) | O(n) | 直观，一次遍历 | 空间随 n 增长 |
| 滑动窗口 | O(n) | O(k) | 空间效率高（k < n） | 需要维护窗口 |
| 暴力法 | O(n×k) | O(1) | 无额外空间 | 极慢，不可用 |

---

### **🔍 两种主流解法的选择**

**当 k 较小时（k << n）：**
- 滑动窗口法更优，空间复杂度 O(k) 远小于 O(n)

**当 k 较大时（k ≈ n）：**
- 两种方法空间复杂度相近（O(n) vs O(n)）
- 哈希表索引法代码更简洁

**当需要保留原数组时：**
- 两种方法都不修改原数组，都可用
