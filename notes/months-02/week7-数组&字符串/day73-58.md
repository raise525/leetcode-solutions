## #58 最后一个单词的长度

**【题目描述】**
给你一个字符串 s，由若干单词组成，单词前后用一些空格字符隔开。返回字符串中最后一个单词的长度。单词是指仅由字母组成、不包含任何空格字符的最大子字符串。

**【关键词】**
字符串遍历 | 反向遍历

---

**【核心技巧】**

#### 一、反向遍历（最优解）

**核心思想：**
从字符串末尾开始向前遍历，先跳过末尾的空格，然后统计最后一个单词的字母个数，直到遇到空格或到达字符串开头。

**解题步骤：**
1. 从字符串末尾开始，跳过所有空格字符
2. 从第一个非空格字符开始计数
3. 继续向前遍历，直到遇到空格或到达字符串开头
4. 返回计数值

**代码实现：**
```
int lengthOfLastWord(string s) {
    int length = 0;
    int i = s.length() - 1;
    
    // 跳过末尾的空格
    while (i >= 0 && s[i] == ' ') {
        i--;
    }
    
    // 统计最后一个单词的长度
    while (i >= 0 && s[i] != ' ') {
        length++;
        i--;
    }
    
    return length;
}
```

**复杂度：**
- 时间复杂度：O(n)，最坏情况下遍历整个字符串一次
- 空间复杂度：O(1)，只使用常数个变量

#### 二、正向遍历（常规思路）

**核心思想：**
遍历整个字符串，遇到非空格字符开始计数，遇到空格则重置计数（但要小心处理单词间多个空格的情况）。

**代码实现：**
```
int lengthOfLastWord(string s) {
    int length = 0;
    int lastWordLength = 0;
    
    for (char c : s) {
        if (c != ' ') {
            // 当前字符是字母，增加当前单词长度
            length++;
            lastWordLength = length;  // 更新最后一个单词长度
        } else {
            // 遇到空格，重置当前单词长度
            length = 0;
        }
    }
    
    return lastWordLength;
}
```

**注意：** 这种方法需要维护两个变量，因为可能在单词中间遇到空格

#### 三、字符串分割法（编程语言特性）

利用编程语言自带的字符串分割功能：
- C++：可以用 stringstream
- Python：可以用 split()
- Java：可以用 split()

**Python 版本示例：**
```
def lengthOfLastWord(s: str) -> int:
    words = s.split()
    return len(words[-1]) if words else 0
```

**【复杂度分析】**

**一、时间复杂度**

详细分析（以反向遍历为例）：

1. 操作次数：
   - 第一个 while 循环：跳过末尾空格，最多 n 次
   - 第二个 while 循环：统计单词长度，最多 n 次
   - 总体最多遍历整个字符串一次

2. 关键点：
   - 最坏情况：字符串全是字母，需要遍历整个字符串 → O(n)
   - 最好情况：最后一个单词很短，且末尾无空格 → 只遍历几个字符

3. 总时间复杂度：**O(n)**
   - 最坏情况：O(n)
   - 平均情况：O(n) 的一部分

**二、空间复杂度**

详细分析：

1. 内存使用情况：
   - 输入参数：string s（不算在内）
   - 函数内部：只创建了 1-2 个 int 变量
   - 没有使用额外的数组或数据结构

2. 关键点：
   - 只有栈上存储的局部变量
   - 没有动态分配内存
   - 无论输入字符串多长，使用的额外空间固定

3. 总空间复杂度：**O(1)**
   - 空间使用与输入规模 n 无关
   - 只使用固定数量的内存

**【个人的感受】**
1. 这道题看似简单，`但陷阱在于字符串末尾可能有空格，不能简单地找最后一个空格`
2. 反向遍历是最直观且高效的方法，从后往前思考往往能简化问题
3. 正向遍历需要处理单词间多个空格的情况，逻辑稍复杂
4. 在工程实践中，使用 split() 最简洁，但面试时最好展示手动实现的思路
5. 有时候最简单的题反而最考验边界条件处理的严谨性
6. 最重要的是你要有一个`解题思路`，如果思路的某一步骤不知道怎么做，完全可以通过`查询`来完成，但是我觉得我的`调试能力`还是很差，基本没用过。
